Added `HttpVideoCacheStore` and the persistence tier's six video-cache routes, the last of MR 2's four store groups to cross the seam. Still inert: nothing constructs it, and `docs/image-dependencies.md` is unchanged. This was the group expected to need a new wire type or a Protocol change, being the only one whose signatures name `MediaDownload` rather than a view type — it needed neither. `MediaDownload` keeps no raw yt-dlp dict (`ytdl_data` is an `InitVar` reduced to six scalars in `__post_init__`), and `clients/http_broker_client.py` had been sending exactly that shape since the broker split; its two private helpers now live beside the type as `media_download_to_dict` / `media_download_from_dict` and serve both callers. A cache hit reattaches the caller's own `MediaRequest` rather than a rebuilt copy, because the copy would be equal in every respect except the `uuid` the cog tracks the download by. The cache ceiling and storage type stay on the far side, unlike `add_items`' `max_size`: a playlist limit belongs to the guild asking, while `max_cache_files` describes the catalog the persistence tier owns.
