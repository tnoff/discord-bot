Bumped the discord_core pin to core-v3.23.0. A track whose cached object fails its digest on fetch is no longer left to fail every replay: the gateway reports a `cache/` key to the broker, which verifies and evicts it, and skips the track. A `queue/` key that fails is skipped without a report. Deploy the broker first; a broker without the route answers the report with a 404, which is logged.
