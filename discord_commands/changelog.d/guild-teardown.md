The pod serves `POST /guilds/{guild_id}/teardown` (#1030), which the gateway calls when a guild's player goes away. It answers 202 once it has started the job, which runs off the guild's command FIFO (`discord_commands/workers/guild_teardown.py`): it clears the guild's queued downloads and searches, pushes `DISCARDED` for each dropped request, blocks both queues for the guild, and deletes the guild's bundles except those of playlist adds it left queued. A repeat while one is running is dropped, a request the broker no longer knows does not stop the rest, and shutdown lets a teardown in flight finish (10 s) before cancelling it. No new config. Deploy this image before the gateway's: until it runs the gateway's teardown requests fail, and queued work for a closed guild is left to the result loop.
