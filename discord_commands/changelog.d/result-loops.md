The pod runs the music result loops (#1030): `process_search_results` pops a resolved search from the broker, cache-checks it and submits the download, and `process_download_results` pops a finished download and queues it for the guild's player through `BrokerPlayerGateway.add_cached`, which wakes the player with a gateway intent. `MusicResultsLoop` moved here from the gateway (`discord_commands/loop_logic/music_results.py`). Both loops report through `LoopHealth` with the same heartbeat names, so the series now carry `job="discord-commands"`; shutdown lets an iteration in flight finish (5 s) before cancelling, because both pops are destructive. No new config. Deploy this image before the gateway's, so the loops are never both absent (the broker holds results until a consumer runs).
