YouTube downloads no longer fail with `Did not get any data blocks` when the only thing missing is the empty final fragment of an HLS stream (format 96, the fallback when YouTube's SABR experiment strips a client's https formats; yt-dlp#14997). `skip_unavailable_fragments` is back to yt-dlp's default (true), and the downloader reads yt-dlp's log to find out which fragment was skipped: the empty final one is accepted, any other skip discards the file and retries on another exit, as before. Every one of the failures traced in the 2026-11-24 episode was on the last fragment, and retries could not help because each attempt got the same manifest. `extra_ytdlp_options: {skip_unavailable_fragments: false}` still makes yt-dlp fail on any skip.
