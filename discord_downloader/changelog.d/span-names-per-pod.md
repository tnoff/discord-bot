Spans are now named after this pod: `music.download_client.create_source` and `music.download_client.upload_s3` became `downloader.create_source` and `downloader.upload_s3`, so a span name says which pod emitted it. Anything that selects on `span_name` must match the new names. In the Discord Health dashboard that is the Download Client Errors and Create Source Durations panels; the Download Client Errors and Discord Cache Upload Failing alerts select on it too (tnoff/docker-apps monitoring/grafana accepts both names during the rollout). The spans keep their kind (CLIENT), attributes and status handling, and the new test `test_create_source_span_name_and_kind_are_the_alerting_contract` pins the name.
